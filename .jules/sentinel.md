## 2024-05-24 - Unsafe lamport arithmetic and RefCell borrow panic prevention
**Vulnerability:** The code used unsafe arithmetic (`+=`, `-=`) for lamports and `.borrow_mut()` on account lamports. This allowed for two critical vulnerabilities: 1. Uncaught `RefCell` double-borrow panics on the Solana runtime when borrowing lamports/data mutably if the same account is used elsewhere simultaneously or calculated concurrently. 2. Arithmetic overflows that would wrap or panic rather than returning a proper program error.
**Learning:** `RefCell` borrows like `.lamports.borrow_mut()` can cause ungraceful program panics in Rust/Solana. Further, since Rust evaluates the left side of an assignment first, performing `.lamports.borrow_mut() = ...` alongside a calculation using `.lamports()` can trigger simultaneous borrows.
**Prevention:** Always use safe accessors `.try_borrow_mut_lamports()?` and `.try_borrow_mut_data()?` to allow the program to fail gracefully with an error rather than panicking. Always pre-compute new values and explicitly check arithmetic with `.checked_add()` and `.checked_sub()`, propagating an error (e.g., `MplCoreError::NumericalOverflowError`) if an overflow/underflow occurs, before performing the mutable borrow.
