## 2024-05-24 - [Fix Panics Caused by Arithmetic Using Direct RefCell Borrows]
**Vulnerability:** Use of direct "+=" and "-=" operators on `try_borrow_mut_lamports()` within `programs/mpl-core/src/utils/account.rs` can cause Rust panics (crashing the program abruptly rather than failing securely with a meaningful error) when multiple borrows of `lamports` occur simultaneously or arithmetic underflow/overflow occurs.
**Learning:** Using `+` and `-` operators alongside `.try_borrow_mut_lamports()?` can cause panic due to either `RefCell` double mutable borrow (e.g., if one side of the assignment tries to read while the other side borrows mutably, although in `try_borrow_mut_lamports()` context it is mostly the arithmetic panics that are unhandled). Even more critical is that arithmetic underflow/overflow inside these operators `+=` and `-=` isn't caught gracefully in Solana programs if `Cargo.toml` specifies panic=abort or standard checks, whereas `checked_add` and `checked_sub` mapped to an error handles this safely.
**Prevention:** In Solana programs, strictly use `.checked_add()` and `.checked_sub()` to perform math on `AccountInfo` fields (like lamports), and bind the calculation to a new variable before assigning it via `try_borrow_mut_lamports()`. Never use `+=` or `-=` directly.
