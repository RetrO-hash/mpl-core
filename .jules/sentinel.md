## 2024-05-17 - Fix ungraceful RefCell panics from lamport assignments
**Vulnerability:** Double-borrow RefCell panics and unhandled integer overflows caused by right-hand evaluation reading `account.lamports()` while simultaneously modifying the account using `**account.lamports.borrow_mut() = ...` or `**account.try_borrow_mut_lamports()? += ...`.
**Learning:** Rust evaluates the left-hand operand of an assignment before the right-hand operand. Calling `lamports()` on an account internally attempts to borrow a RefCell that was already mutably borrowed by the left side of the assignment, resulting in an immediate program panic. Additionally, `+=` and `-=` bypass the ability to check for underflow/overflow, which is an additional critical vulnerability.
**Prevention:** Compute the new lamport value completely on its own line using safe arithmetic (`.checked_add()`, `.checked_sub()`) BEFORE attempting to borrow the account mutably via `try_borrow_mut_lamports()?`. Never use `**account.lamports.borrow_mut()` directly or the unsafe `+=` / `-=` operators for lamports.
