## 2024-05-30 - Fix Potential RefCell Double-Borrow Panics and Unsafe Arithmetic Operations
**Vulnerability:** Solana `AccountInfo` lamports and data are protected by `RefCell`. Using `borrow_mut()` multiple times, or coupling `+=` and `-=` operators on the same value being borrowed, can trigger program panics (double borrows). Furthermore, arithmetic without `checked_add` / `checked_sub` can trigger underflow/overflow panics, which causes ungraceful failing, lost gas without clear errors, and DoS.
**Learning:** Rust evaluates the left-hand operand of an assignment first. For `**account.try_borrow_mut_lamports()? += amount`, the `RefCell` is mutably borrowed *before* calculating `amount` (which might read the same account), leading to a panic. This codebase previously had direct assignments without checked arithmetic.
**Prevention:** Always use `.try_borrow_mut_lamports()?` rather than `.borrow_mut()` to return a graceful ProgramError on failure rather than panicking. Always decouple mathematical operations from the assignment: calculate the new value first using `checked_add`/`checked_sub`, map missing options to a clean error like `MplCoreError::NumericalOverflowError`, and then assign to the borrowed memory.
