## 2024-06-25 - Fix RefCell Borrow Panics and Safe Arithmetic in Account Lamports Modification
**Vulnerability:** Unsafe `.borrow_mut()` and arithmetic assignment (`+=`, `-=`) used directly on `AccountInfo::lamports` which can cause critical `RefCell` double-borrow panics and fail securely. Integer arithmetic operators lack overflow/underflow protection.
**Learning:** Rust evaluates the left-hand operand of an assignment first, so modifying lamports on a mutably borrowed `AccountInfo` while calculating the right side using the same `AccountInfo` causes a runtime double-borrow panic instead of failing the transaction securely. In Solana programs, panics are severe crashes, breaking transaction atomic guarantees. Additionally, `+` and `-` operations are unsafe without explicit `.checked_add()` and `.checked_sub()`.
**Prevention:** Always pre-calculate the new value using safe `.checked_add()` or `.checked_sub()` before assigning it back to the mutably borrowed account field using `try_borrow_mut_lamports()?`. Never use `.borrow_mut()` directly on `AccountInfo` fields.
