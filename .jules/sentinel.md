## 2024-05-18 - Fix RefCell Double Borrow Panics (DoS) due to Assignment Evaluation Order
**Vulnerability:** Critical DoS vulnerability where Solana programs panic during execution due to `RefCell` double borrow errors. The code assigned a newly calculated lamport value directly to the result of `account.lamports.borrow_mut()`, but calculated the right-hand side using `account.lamports()`, which calls `.borrow()`. Because Rust evaluates the left-hand side of an assignment first, the mutable borrow was held while the immutable borrow was attempted, resulting in a runtime panic. Unsafe `+=` and `-=` operators were also used alongside `.try_borrow_mut_lamports()`.
**Learning:** Rust evaluates assignments left-to-right. When modifying `AccountInfo` fields (which are wrapped in `RefCell`), one must never combine a mutable borrow on the left-hand side with an immutable borrow on the right-hand side in the same statement. Furthermore, unsafe operators like `+=` and `-=` should be avoided in favor of `.checked_add` and `.checked_sub`.
**Prevention:** Always compute the new value in a separate statement using `.lamports()` and checked math before acquiring a mutable reference using `.try_borrow_mut_lamports()?` to assign the value.
