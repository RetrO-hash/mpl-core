## 2024-06-25 - Prevent Ungraceful Panics in Lamport Assignments
**Vulnerability:** Ungraceful panics due to direct `RefCell` borrowing and unsafe arithmetic in Solana accounts. Using `.lamports.borrow_mut()` directly on an `AccountInfo` and using `+=`/`-=` operators for lamport assignments can lead to runtime `RefCell` borrow panics or arithmetic overflow/underflow panics, which fail ungracefully instead of returning a predictable `ProgramError`.
**Learning:** Rust evaluates the left-hand operand of an assignment first. Attempting to calculate the right-hand side simultaneously (e.g., via `+=` or `-=`) while reading from the same account can cause runtime `RefCell` borrow panics. Direct use of `.borrow_mut()` circumvents safe error handling, while unsafe arithmetic can panic on underflow/overflow.
**Prevention:** In Solana programs, strictly avoid `.lamports.borrow_mut()` and instead use `.try_borrow_mut_lamports()?` to return a clean error if a double-borrow occurs. To modify balances, use `.lamports()` for reading and compute the new value with checked arithmetic (`.checked_add()` / `.checked_sub()`) before the assignment statement. Map `None` from checked math to an error using `.ok_or(MplCoreError::NumericalOverflowError)?`. Completely avoid the `+=` and `-=` operators.
