## 2024-05-24 - Unsafe Lamport Operations and RefCell Panics
**Vulnerability:** Assigning values to `account.lamports.borrow_mut()` directly using operators like `+=` or inline expressions that also call `account.lamports()` causes runtime `RefCell` panics. Specifically, `**dest1_info.lamports.borrow_mut() = dest1_info.lamports() + amount;` fails because the left side borrows mutably before the right side attempts an immutable borrow on the same `RefCell`.
**Learning:** Rust evaluates the left hand side of an assignment first. Trying to compute a value based on an account's lamports and then assign it back in a single statement using direct `.borrow_mut()` causes an ungraceful borrow conflict that brings down the program.
**Prevention:** Compute the new value prior to the assignment using standard variables (`let current = dest_info.lamports(); let new = current + amount;`), and apply the changes using `**account.try_borrow_mut_lamports()? = new;`. This prevents double borrow panics and safely returns an error if `try_borrow_mut_lamports` fails. Avoid the `+=` and `-=` operators entirely for these updates.
