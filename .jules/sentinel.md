## 2024-05-24 - [Replace Unsafe Account Modification Operations]
**Vulnerability:** Found direct unsafe modifications of lamports using the `-=` and `+=` operators (e.g. `**account.try_borrow_mut_lamports()? -= amount`), as well as `data.borrow_mut()` which can lead to unhandled runtime panics and double borrows. Further `unwrap()` calls on options for initialization values were causing panics instead of safe propagation.
**Learning:** Rust left-to-right evaluation means if `lamports()` is read dynamically on the right hand while mutably borrowed on the left hand, it will cause a borrow panic. Using standard compound assignments is risky. Double borrows through `borrow_mut()` instead of `try_borrow_mut_data()` bypasses gracefully handling borrow errors via `ProgramError`.
**Prevention:** Strictly enforce `.lamports()` reads before assignment, compute new values using `.checked_add()` or `.checked_sub()`, and only then safely assign via `**account.try_borrow_mut_lamports()? = new_val`. Replace all `data.borrow_mut()` with `try_borrow_mut_data()?` for safe error propagation without panics.
