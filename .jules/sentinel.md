## 2024-05-18 - [Prevent RefCell Panics and Unsafe Math in Lamport Mutations]
**Vulnerability:** The code in `close_program_account` and `resize_or_reallocate_account` directly accessed lamports via `lamports.borrow_mut()`, used unsafe mathematical operators (`+=`, `-=`), and assigned values to `AccountInfo` fields using computations that borrow from the same fields, leading to possible unexpected RefCell panics.
**Learning:** `lamports.borrow_mut()` and operations evaluating an arithmetic modification on an actively borrowed account risk double-borrowing that throws an ungraceful runtime panic instead of returning `ProgramResult`. In Solana smart contracts, causing a panic can be an attack vector or unexpectedly cause locked funds.
**Prevention:** Always use safe `try_borrow_mut_lamports()?`, separate calculation variables before assignment, use `checked_add` and `checked_sub` mapped to `NumericalOverflowError`, and never chain borrows inside unsafe arithmetic assignments.
