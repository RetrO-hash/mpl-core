## 2024-05-18 - Prevent Integer Overflow and Double Borrow Panics in Account Modifications
**Vulnerability:** Use of direct `.borrow_mut()` and unchecked `+=`/`-=` arithmetic on `AccountInfo` lamports creates multiple panic vectors (CRITICAL).
**Learning:** `RefCell` borrow panics (`.borrow_mut()`) occur if the account is borrowed twice, tearing down the transaction. Unchecked arithmetic on balances can silently overflow/underflow or panic in debug mode. Furthermore, assigning the result of `checked_add/sub` directly into a mutably borrowed account field using `**account.try_borrow_mut_lamports()? = ...` causes a double-borrow panic if the RHS of the assignment also reads from the account (e.g., via `lamports()`).
**Prevention:** Always use `.try_borrow_mut_lamports()?` to return a graceful `ProgramError::AccountBorrowFailed` instead of panicking. Always use `.checked_add` and `.checked_sub` mapped to an explicit error (e.g., `MplCoreError::NumericalOverflowError`). Most importantly, calculate the new value *before* initiating the mutable borrow for assignment.
