## 2024-05-30 - Prevent Solana RefCell Double Borrows and Arithmetic Underflow/Overflow Panics
**Vulnerability:** Programs manipulated lamports and data via `account.lamports.borrow_mut()` and unsafe arithmetic assignments like `+=`/`-=` on borrowed accounts. In Rust, these expressions evaluate left-to-right, causing right-side variables to be evaluated while left-side is mutably borrowed, leading to RefCell `AlreadyBorrowed` panics. Additionally, unsafe operators fail via program abort on overflow/underflow, creating a denial of service (DoS) and fund loss vector.
**Learning:** Never directly mutate `.borrow_mut()` on AccountInfo fields. Instead, calculate the final value correctly on the right side using `.lamports()` and `checked_add`/`checked_sub` prior to performing the mutation on a new `.try_borrow_mut_lamports()?`.
**Prevention:** Strictly enforce `checked_add()` and `checked_sub()` for all numerical operations. Use `try_borrow_mut_lamports()?` and `try_borrow_mut_data()?` for all mutable accesses to prevent `RefCell` panics. Return an error on failure instead of allowing `unwrap()` or `expect()`.
