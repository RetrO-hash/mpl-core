## 2024-05-18 - [Fix RefCell borrow panics from unsafe operators]
**Vulnerability:** Double borrows via `RefCell` when computing and simultaneously assigning (using `+=` or `-=`) lamport changes on an account in `programs/mpl-core/src/utils/account.rs`, leading to runtime ungraceful panics and potential denial of service if exploited. In addition, using unwraps directly when mapping enumerations like `Key` could panic unexpectedly.
**Learning:** In Solana Rust programs, `AccountInfo` fields like `.lamports` and `.data` use `RefCell` for mutability. Assignments like `**account.try_borrow_mut_lamports()? += amount` or `**account.lamports.borrow_mut()` borrow mutably while computing the right-hand expression. If the expression internally triggers another borrow of the same account, the program will panic ungracefully due to double-borrowing rules.
**Prevention:** Compute the exact new lamports amount *before* the assignment using safe arithmetic methods (`.checked_add()` and `.checked_sub()`) combined with `.ok_or(MplCoreError::NumericalOverflowError)?`. Afterwards, apply the assignment safely to `.try_borrow_mut_lamports()?[0]`. Additionally, substitute `.unwrap()` and `.borrow_mut()` with `.ok_or(...)` and `.try_borrow_mut_data()?`.
