## 2024-05-18 - Prevented Unsafe Lamport Modification
**Vulnerability:** In `programs/mpl-core/src/utils/account.rs`, lamport modifications were using the `+=` and `-=` operators directly on `**account.try_borrow_mut_lamports()?`. This bypasses Rust's safety checks for integer arithmetic and could lead to runtime panics (overflow/underflow) if lamport balances are large enough or miscalculated. Furthermore, the previous logic could potentially suffer from aliased borrow issues if multiple mutable borrows to the same account happened without sequencing.
**Learning:** Solana smart contracts must strictly use checked arithmetic (e.g., `.checked_add()`, `.checked_sub()`) for all lamport modifications to prevent panics and potential exploits where an attacker might force an overflow to mint lamports or cause a denial-of-service via panic. Additionally, to avoid `RefCell` borrow panics when updating lamports on multiple accounts that might alias each other, calculate the new values before assigning them and update them sequentially.
**Prevention:** Always use `.checked_add()` and `.checked_sub()` for lamport arithmetic, and explicitly assign the result. Never use `+=` or `-=` directly on lamport borrow mutators.
