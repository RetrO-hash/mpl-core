## 2024-11-20 - [RefCell Double Borrow Panics due to Left-Hand Side Assignment Computation]
**Vulnerability:** In Rust, assigning a newly computed value to a dereferenced RefCell borrowed object using `borrow_mut()` on the left-hand side (e.g. `**dest.lamports.borrow_mut() = dest.lamports().checked_add(x)?`) causes a runtime panic due to double-borrowing (violating RefCell's memory safety rules). This leads to ungraceful transaction failures and a potential DoS attack vector in Solana smart contracts. Additionally, relying on `borrow_mut()` is unsafe.
**Learning:** Rust evaluates the left-hand operand of an assignment before evaluating the right-hand operand. If the right-hand operand reads from the same account being mutably borrowed by the left side, it leads to a panic. This is unique to smart contracts borrowing mutable lamports.
**Prevention:** Always pre-compute the right-hand side of assignments before performing the mutable borrow. Also, avoid using `borrow_mut()` and instead use the safer `.try_borrow_mut_lamports()?` and `.try_borrow_mut_data()?` which return descriptive errors instead of panicking.
