## 2024-05-30 - Prevent lamports manipulation panics from += and -= operators
**Vulnerability:** In `programs/mpl-core/src/utils/account.rs`, modification of an account's `try_borrow_mut_lamports()?` was done via unsafe integer arithmetic using `+=` and `-=` assignment operators. When these operators overflow or underflow (due to math logic error, or malformed/maliciously crafted input leading to a large diff), they will trigger an immediate program panic, bypassing clean error handling. This is a vector for Denial of Service and unintended resource states in Solana.
**Learning:** Rust's standard arithmetic operators panic on overflow/underflow in debug/safe math contexts, and can result in unsafe wraparound in some build targets if not explicitly bounded. In Solana smart contracts, you should *always* use the `.checked_*` mathematical functions (e.g., `checked_add`, `checked_sub`) and handle the `None` case securely by returning a typed program error.
**Prevention:** Always read the current lamports (e.g., `account.lamports()`), compute the new balance using `.checked_add()` or `.checked_sub()`, and explicitly assign the result back: `**account.try_borrow_mut_lamports()? = new_lamports`.
