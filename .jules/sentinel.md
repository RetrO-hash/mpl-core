## 2024-05-30 - Fix Double Borrow Panics on Account Lamports
**Vulnerability:** The code directly uses `.lamports.borrow_mut()` on `AccountInfo` structs to update lamports, and evaluates calculations while holding this borrow (e.g., `**account.lamports.borrow_mut() = account.lamports().checked_add(...)`). It also utilizes unsafe `+=` and `-=` operators (e.g. `**target.try_borrow_mut_lamports()? -= amount`) and updates aliased accounts without read-compute-write separation.
**Learning:** Using `.borrow_mut()` on `RefCell` fields like lamports or data will cause an ungraceful panic if the field is already borrowed, instead of returning an error. Furthermore, performing calculations that read the account's lamports *during* the assignment statement where a mutable borrow is held causes a runtime RefCell double-borrow panic. Lastly, using `+=` or `-=` or buffering reads for aliased accounts can result in overwriting updates or panics.
**Prevention:** Always use `.try_borrow_mut_lamports()?` and `.try_borrow_mut_data()?`. Pre-compute the new lamports value using `.lamports()` before making any assignment to `try_borrow_mut_lamports()?` to ensure strict separation of reads and writes. Process one account completely (read-compute-write) before moving to the next.
