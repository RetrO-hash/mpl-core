## 2024-06-25 - Prevent ungraceful panics and lamport aliasing bugs
**Vulnerability:** Ungraceful panics caused by `RefCell` double-borrows (e.g. `lamports.borrow_mut()`) and arithmetic operations (e.g. `+=`/`-=`) on potentially aliased accounts.
**Learning:** Using `+=` or `-=` on lamport balances while simultaneously borrowing them can lead to `RefCell` panics. Additionally, buffering lamport balances for multiple accounts before applying updates causes functional regressions if those accounts are aliased (i.e. refer to the same underlying account), as later updates will overwrite earlier ones.
**Prevention:** Strictly use `.try_borrow_mut_lamports()?` instead of `.borrow_mut()`. When updating lamports, map mathematical operations with `.checked_add()` and `.checked_sub()` to a clean error like `MplCoreError::NumericalOverflowError`. For multiple accounts, perform an alternating read-compute-write sequence for each account sequentially to ensure changes are immediately reflected in case of aliasing.
