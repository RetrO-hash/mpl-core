## 2024-05-18 - Prevent Unsafe unwraps in Solana Processors
**Vulnerability:** Safe extraction of `Option` types with `.unwrap()` in Solana instructions, specifically `ctx.accounts.collection.unwrap()` in `burn.rs` and `create.rs`, can cause ungraceful program panics and DoS vectors instead of returning standard program errors if the account isn't provided or parsed correctly. Similar panics happen when `borrow_mut` and reading values on RefCells are done in the same step.
**Learning:** In the Solana environment, missing required accounts or data structures wrapped in `Option` should fail securely by converting to a Program Error (e.g., `.ok_or(MplCoreError::MissingCollection)?`), returning clear, expected responses to users and clients instead of crashing the program silently. Simultaneous mutable borrows and reads on `RefCell` should also be avoided.
**Prevention:** Always use safe `Option` handling (like `.ok_or(...)?`) when extracting accounts or values from context structs in Solana processors, avoiding `unwrap()` or `expect()`. Use `try_borrow_mut_lamports` correctly when mutating accounts.
