## 2024-05-24 - Solana RefCell Double-Borrow Panics on Assignment
**Vulnerability:** Ungraceful Program Panics (DoS vector via double borrowing and unsafe arithmetic operators `+=` / `-=`).
**Learning:** In Solana, account `lamports` and `data` are stored in a `RefCell`. When performing combined operations like `**account_info.try_borrow_mut_lamports()? += amount`, Rust evaluates the mutable borrow on the left side before calculating the right side. If the right side or a related calculation also reads from the account (e.g. implicitly accessing the same `RefCell`), or if `try_borrow_mut_lamports()` is mixed with `lamports()` inline, it can cause a `BorrowMutError` panic. Additionally, using `+=` or `-=` does not allow returning a clean error if arithmetic underflows/overflows.
**Prevention:** Always read the current value using `.lamports()`, calculate the new value using safe arithmetic (`.checked_add()`, `.checked_sub()`), map errors cleanly, and then assign the value using `.try_borrow_mut_lamports()?` in a separate statement. Never use `+=` or `-=` directly on `RefCell` borrows in Solana.
