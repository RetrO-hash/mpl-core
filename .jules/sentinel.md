## 2024-05-18 - [CRITICAL] Fix ungraceful panics and integer overflow in lamports handling
**Vulnerability:** Ungraceful panics during `lamports` mutations in Solana. By using `.lamports.borrow_mut()`, `unwrap()`, and evaluating variable borrows inline `**dest.lamports.borrow_mut() = dest.lamports().checked_add(x)?`, the contract is susceptible to double-borrow `BorrowMutError` panics from the `RefCell`, as well as runtime arithmetic panics via `+=`/`-=`.
**Learning:** Rust evaluates the left side of an assignment first. Getting a mutable borrow on the left side, then asking for an immutable borrow of the same variable on the right side causes an instant double-borrow panic. Also, any panic crashes the entire VM invocation rather than rolling back gracefully.
**Prevention:** Always calculate the new value *before* performing the assignment. Use fallible methods like `.try_borrow_mut_lamports()?` and safe arithmetic `.checked_add()?` combined with local program errors to exit gracefully.
