## 2024-05-18 - Unsafe RefCell Borrow Panics and Arithmetic Overflows
**Vulnerability:** Code modifying Solana account lamports and data was directly calling `.lamports.borrow_mut()` and `.data.borrow_mut()` and performing compound unsafe assignments (`+=` and `-=`).
**Learning:** In Solana Rust programs, `lamports` and `data` are stored inside a `RefCell`. Directly calling `borrow_mut()` without checks can cause runtime panics (e.g. `AlreadyBorrowed`) resulting in program crashes, rendering contracts open to griefing/DoS attacks. Similarly, performing unsafe `+=` and `-=` assignments on the left side of an expression while calculating the right side from the same account triggers the double borrow panic, because Rust evaluates the left side first.
**Prevention:** Always use safe accessors `.try_borrow_mut_lamports()?` and `.try_borrow_mut_data()?` to bubble up an error cleanly instead of panicking. Calculate the final value before assignment using `.checked_add()` and `.checked_sub()`, assigning it fully evaluated.
