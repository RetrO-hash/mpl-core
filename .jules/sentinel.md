## 2024-05-24 - [CRITICAL] Unsafe lamport arithmetic and mutable data borrow panics
**Vulnerability:** In `programs/mpl-core/src/utils/account.rs`, there were instances of unsafe arithmetic operators (`+=`, `-=`) being used for modifying lamport balances and unsafe mutable borrows (`borrow_mut()`) used on `account.lamports` and `account.data`.
**Learning:** Using `+=` and `-=` can cause severe panics due to integer overflow/underflow, while using `borrow_mut()` on RefCell structs causes program aborts if the borrow is already taken. Solana programs must safely fail returning an error rather than panicking, especially when handling native lamport quantities.
**Prevention:** Always use `.checked_add()` and `.checked_sub()` for all numerical operations modifying lamports, mapped to an appropriate error (e.g. `MplCoreError::NumericalOverflowError`). Use `.try_borrow_mut_lamports()?` and `.try_borrow_mut_data()?` to safely acquire mutable access. Also ensure the new values are calculated before the assignment, as Rust evaluates the left-hand operand of an assignment first, meaning trying to assign and read in one go on the same borrowed object can trigger a runtime RefCell borrow panic.
