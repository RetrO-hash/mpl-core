## 2024-05-31 - [RefCell Double Borrow Panic in Collect]
**Vulnerability:** Double borrow of `lamports` RefCell on an `AccountInfo` could cause a deterministic panic. Specifically, `**dest1_info.lamports.borrow_mut() = dest1_info.lamports().checked_add(...)` tries to `borrow_mut()` while `.lamports()` implicitly borrows the same underlying `RefCell`. In Rust, the LHS of an assignment is evaluated first, so it borrows mutably, then the RHS attempts to borrow immutably, causing a panic.
**Learning:** This could be exploited by an attacker to cause deterministic panics during the `collect` instruction, potentially halting the process or disrupting the system if other programs rely on `collect` not panicking. Also, relying on panics for control flow/errors is discouraged.
**Prevention:** Compute the values on the RHS first, save them to a local variable, and *then* assign them to the mutably borrowed target. Better yet, use `.try_borrow_mut_lamports()?` to ensure graceful failure (error returned) instead of a panic if a double-borrow ever happens.
