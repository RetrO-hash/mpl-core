## 2024-03-29 - [CRITICAL] Fix RefCell panics, unwrap, and unsafe arithmetic in account modifications
**Vulnerability:** In Solana programs, modifying an `AccountInfo` lamports directly with `.lamports.borrow_mut()` causes ungraceful program panics if the account is already borrowed. Additionally, simultaneously calculating and assigning lamports (using `+=` or `-=`) can lead to similar borrow errors because Rust evaluates the left-hand assignment first. Finally, direct arithmetic operators can cause underflow/overflow panics if lamport limits are exceeded. A generic `.to_u8().unwrap()` on the uninitialized Key type can also cause generic program termination instead of a controlled error.
**Learning:** These practices bypass the safe `Result` error boundary, crashing the Solana program abruptly instead of bubbling up a meaningful error that allows the caller to recover or debug gracefully. Unsafe math with unchecked assignments adds vectors for unintended arithmetic overflows and panics.
**Prevention:** Always use `.try_borrow_mut_lamports()?` and `.try_borrow_mut_data()?`. Do not use `+=` or `-=`; instead use `.lamports()` to get the current amount, safely compute the new amount using `.checked_add()` or `.checked_sub()`, and only then assign it to the mutably borrowed lamports reference. Replace `.unwrap()` with `.ok_or()` to propagate precise program errors.
