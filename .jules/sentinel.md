## 2024-05-18 - Fix Double-Borrow Panics and Unsafe Arithmetic in Account Modifications
**Vulnerability:** Core functions `close_program_account`, `resize_or_reallocate_account`, and `collect` directly accessed `AccountInfo` `RefCell` using `.borrow_mut()` while simultaneously computing new balances or data sizes, causing immediate program panics ("RefCell already borrowed"). Additionally, lamports adjustments used unsafe `+=` and `-=` operators instead of safe math.
**Learning:** In Rust/Solana, evaluating left-hand operands happens first; using `**account.lamports.borrow_mut() = ...` locks the `RefCell` mutably. If the right side also tries to read/borrow the same `RefCell` (e.g. `...lamports.checked_add()`), it causes a double borrow panic.
**Prevention:** Always compute the new value and store it in a local variable before assigning it back to a `try_borrow_mut_*` bound `AccountInfo` field. Replace unsafe arithmetic operators (`+=`, `-=`) with `.checked_add()` / `.checked_sub()`. Avoid `.unwrap()` on `.to_u8()` mapped enums to avoid unwanted DoS-like program halts.
