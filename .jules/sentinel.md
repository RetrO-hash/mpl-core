## 2024-03-28 - [High] Prevent RefCell double borrow panics during lamport modification
**Vulnerability:** Double borrow `RefCell` panics and potential overflows when modifying Solana account lamports using direct `.lamports.borrow_mut()` and unsafe `+=` / `-=` assignment operators.
**Learning:** Rust evaluates the left-hand operand of an assignment before the right-hand operand. If the left-hand side mutably borrows the lamports `RefCell` (e.g., `**account.try_borrow_mut_lamports()?`), and the right-hand side simultaneously attempts to read the same account's lamports (e.g., `account.lamports()`), a runtime double-borrow panic occurs, crashing the program gracefully instead of returning a generic error, which can be an attack vector for DoS.
**Prevention:** Always compute the new value of the lamports before assigning it to the mutable borrow of the account. Avoid using `+=` or `-=` directly on the mutable borrow. Use `.try_borrow_mut_lamports()?` instead of `.lamports.borrow_mut()` to return a clean program error instead of a direct uncatchable panic.
